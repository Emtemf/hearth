# UI 设计

## 定位与原则

- **桌面优先**：最小宽度 1280px，不做移动端适配
- **移动端入口是 IM**（飞书/Telegram），Web UI 是桌面管理界面
- **操作密度优先于美观**：这是个人工具，信息密度比空白感更重要
- **实时感**：运行中的任务要让人感觉"在看"，不是"在查"

## 代码规范

### TypeScript
```json
// tsconfig.json 关键配置
{
  "strict": true,
  "noUncheckedIndexedAccess": true,
  "noImplicitReturns": true
}
```
- 禁止 `any`，用 `unknown` + 类型收窄
- API 响应类型和后端 schema 手动对齐（后端改了 API，前端必须同步更新类型）
- 组件 props 用 `interface`，工具类型用 `type`

### 命名约定
```
组件文件      PascalCase.tsx        TaskDetailPage.tsx
hook 文件     camelCase.ts          useTaskEvents.ts
工具文件      camelCase.ts          formatDuration.ts
Store 文件    camelCase.store.ts    inbox.store.ts
CSS class     Tailwind utility，不写自定义 class（除非 @layer components）
```

### 状态管理分工（不能混用）
```
服务端数据（API 返回的）  → React Query（useQuery / useMutation）
实时推送数据             → React Query + SSE（用 queryClient.setQueryData 更新缓存）
UI 交互状态             → Zustand（侧边栏、选中、hover 等）
表单状态                → React Hook Form + Zod（不用 Zustand 管表单）
URL 状态                → React Router searchParams（filter、tab 等）
```

**禁止**：用 `useState` 管服务端数据；用 Zustand 管 API 数据；用 React Query 管 UI 状态。

### 组件规范
- 每个组件一个文件，文件名和组件名一致
- Props 接口紧跟在 import 之后，组件之前
- 禁止超过 200 行的组件文件，超了就拆
- 禁止在 JSX 里写内联样式（用 Tailwind class）
- 所有可交互元素必须有 `aria-label` 或可见文字标签（可访问性）

### 错误处理
- React Query 的错误用 `ErrorBoundary` + `error.tsx` 组合处理
- API 错误统一解析后端信封的 `error.code` 字段，不直接展示 HTTP 状态码
- 用户可操作的错误（如网络断开）用 Toast 提示，不用 alert

```
│ ✗ 修复 #234 bug       failed     12m    $0.3    │
└─────────────────────────────────────────────────┘
```

### 任务详情 — 三 Tab

**Tab 1：时间线（Gantt）**
每个 session 一行，横轴是时间，运行中的任务实时延伸。
颜色：running=蓝，succeeded=绿，failed=红，awaiting_human=橙。

**Tab 2：调用图（xyflow Graph，不假定输入永远是 DAG）**
默认节点 = Session，边 = Internal Dispatch（request/consult/notify/escalate 颜色不同）；另提供 Task Tree 视图，
展示 request 创建的 Child Task、预算与级联取消，禁止把业务分解树和 Session 协作图混为一张图。
点节点 → 右侧面板展示 session 摘要 + system prompt 预览。
点边 → 展示 Dispatch 内容、childTaskId、Artifact 材料和 Claim/Verification 状态；有 Artifact 但未验证时明确标
“待验证”，不得显示成已证明。
实时更新：新 session 启动时节点出现，新 Dispatch 消息时边出现。
布局与遍历必须使用 visited set；self-loop、cycle、重复边和 orphan 节点降级展示并标记数据异常，禁止递归组件因坏图栈溢出。

**Tab 3：Exchange 时间线（Time-Travel Debugging）**
每次模型调用一条记录，支持步进导航：← 上一步 / → 下一步 / 跳到任意步。
点任意 exchange 展开：完整 system prompt + messages + tool calls + cost + stop reason。
目的：找到 agent 做错决策的具体那一步，不需要复现——数据面已经录制了全量 exchange。

**关键**：这不是新功能，是把已有的 exchange 数据做成可导航的时间线。
后端先用 `GET /api/v1/sessions/:id/exchanges?page=P&size=N` 拉有序列表，点选后用
`GET /api/v1/sessions/:sessionId/exchanges/:exchangeId` 加载详情。前端的“第 N 步”是当前排序结果中的 UI
索引，不新增另一套后端 `index` 语义。

## 实时数据策略

| 数据 | 更新方式 | 频率 |
|---|---|---|
| 任务状态变更 | SSE `task.status_changed` | 事件驱动 |
| Session 就绪/激活/终止 | SSE `session.ready/active/terminated` | 事件驱动 |
| Token 用量 | SSE `exchange.response`（每次模型调用后） | 事件驱动 |
| 调用图新节点/边 | SSE `dispatch.dispatched` | 事件驱动 |
| Inbox 新条目 | SSE `inbox.created` | 事件驱动 |
| Worker 心跳 | 轮询（30s），不用 SSE | 低频 |

前端 SSE 连接：`GET /api/v1/sse?traceId=xxx`（过滤到当前任务）或 `GET /api/v1/sse`（全局流）。
断线自动重连（`EventSource` 原生支持），重连后服务端从最后的 `publicationSeq` 续传。

## 实时连接状态与最终收敛

SSE 不能被当作唯一事实源。全局连接状态必须显式展示：

```text
LIVE          已连接，event watermark 与服务端一致
RECONNECTING  短暂断线，正在按 Last-Event-ID 重连
STALE         无法确认当前数据新鲜度；页面保留旧数据但显示最后同步时间
RECONCILING   cursor 过期或版本跳跃，正在重新拉 REST snapshot
OFFLINE       多次失败，停止声称页面实时；提供手动重试
```

处理规则：

1. SSE event 带唯一单调 `publicationSeq`、内部 `eventId`、`aggregateVersion`、相关 `invocationId`，前端按 publicationSeq 去重。
2. 发现 aggregate version 跳跃，进入 RECONCILING，不猜缺失状态。
3. 服务端发送 `cursor.expired` 控制事件时，前端主动关闭旧 EventSource，按事件里的 snapshotUrl 拉快照；snapshot 带 `eventWatermark`，原子替换 React Query 缓存后用 `?after={eventWatermark}` 新建连接。浏览器不能给新 `EventSource` 手工设置 `Last-Event-ID` header。
4. 网络断开时不静默显示旧状态；顶栏显示状态与“最后同步时间”。
5. “正在回复/执行”以非终态 Invocation 为准，不以长期 Session 进程是否存活为准。
6. LIVE 事件和 REST snapshot 竞争时按 aggregate version 决定，禁止用到达时间覆盖新数据。

## 生产部署注意事项

### SPA 路由回退（必须配，否则刷新页面 404）

React Router 的客户端路由在 Spring Boot 直接 serve 静态文件时会 404。
需要在 Spring Boot 加一个 fallback controller：

```java
@Controller
public class SpaFallbackController {
    // 只匹配已知 SPA 前缀；不要用会吞掉 /api、/actuator 或静态资源 404 的全局通配。
    @RequestMapping(value = {
        "/",
        "/tasks", "/tasks/{*path}",
        "/sessions/{*path}",
        "/inbox", "/profiles", "/workers", "/memory", "/settings"
    })
    public String forward() {
        return "forward:/index.html";
    }
}
```

### CORS（开发时需要，生产时不需要）

开发时：Vite dev server 在 :5173，通过代理转发 `/api` → `:4517`，不存在跨域。
生产时：前端和后端同源（同一个 Spring Boot 服务），不需要 CORS 配置。

如果未来前端独立部署（不打包进 jar），才需要配。届时在 Spring Boot 加：
```java
@Bean
public CorsConfigurationSource corsConfigurationSource() { ... }
```

现在不配，等需要时再加。

不需要漂亮，只需要能用：
1. Session 列表（时间、模型、token 用量、observability 等级）
2. 点进去看 system prompt 全文（CodeMirror，M1 就要，因为 system prompt 很长）
3. 完整对话历史（工具调用简单展示，不需要折叠交互）
4. `/actuator/health` 状态（可以就是个绿点）

M1 **不做**：调用图、Gantt、Inbox 界面、Worker 管理页、记忆浏览器。
